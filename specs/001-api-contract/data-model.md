# Phase 1 Data Model: Anonymous Battleship API Contract

## Model purpose

This is the language-neutral wire model for the contract feature. It describes public values,
relationships, validation, projections, and transitions. It does not prescribe Java classes,
frontend state, storage maps, locks, subscribers, or rule-engine implementation.

## Wire primitives

| Primitive | Wire shape | Validation and meaning |
|---|---|---|
| `ContractVersion` | string | Constant `1.0.0` for the initial release. Not an API path major or game revision. |
| `ApiMajor` | integer | Constant `1` for `/api/v1`. |
| `GameId` | string | Canonical unpadded base64url of exactly 16 bytes: 22 characters matching `^[A-Za-z0-9_-]{21}[AQgw]$`, plus decode/re-encode equality. Public locator only; never authorization. |
| `ServerEpoch` | string | Lowercase canonical UUID v4 generated per process start. Old revisions are incomparable after change. |
| `CommandId` | string | Lowercase canonical UUID v4 generated by the client; uniqueness scope is game + membership. |
| `ShipId` | string | Opaque 8–64 base64url characters, stable within one game and echoed only in caller-authorized contexts. |
| `CorrelationId` | string | Opaque 16–64 base64url characters; bounded diagnostic correlation, not identity. |
| `Instant` | string | UTC RFC 3339 with exactly millisecond precision: `YYYY-MM-DDTHH:mm:ss.SSSZ`. |
| `DurationMs` | integer | 0 through `9007199254740991`; authoritative elapsed milliseconds. |
| `Revision` | integer | 0 through `9007199254740991`; monotonic within one game/process. |
| `Coordinate` | object | Required zero-based `rowIndex` and `columnIndex`; each bounded by selected ruleset dimensions. |
| `DisplayName` | string | NFC-normalized, Unicode-edge-trimmed, 1–32 Unicode code points, no control characters; plain text only. |
| `GameStateTag` | string | Opaque strong entity tag matching `"bs-g1.<base64url>"`; binds game + `gameVersion`. |
| `SnapshotTag` | HTTP header | Opaque strong entity tag matching `"bs-s1.<base64url>"`; binds epoch + game + caller projection + `snapshotRevision`. |
| `AccuracyRatio` | number or null | `null` iff shots = 0; otherwise 0..1 rounded half-up to at most four fractional digits. |

All JSON integers use the safe-integer bound so an independent TypeScript consumer does not lose
precision. Request objects reject unknown properties. Response/event objects require the named v1
fields but tolerate future optional properties.

## Relationship overview

- One anonymous browser identity has zero or more game memberships.
- One game has exactly one owner membership and zero or one guest membership.
- One browser identity cannot hold both memberships in the same game.
- One game selects exactly one immutable ruleset and one concealed starting seat at creation.
- One unused invitation belongs to one waiting game; rotation replaces it, redemption consumes it,
  and abandonment/expiry revokes it.
- Every authenticated representation is projected for exactly one current or retained membership.
- Each game has one `gameVersion`; each caller-safe representation change has one
  `snapshotRevision`; caller snapshot tags may differ at the same revision.
- Each membership has bounded command receipts and at most two retained leave receipts per seat.
- Each membership has at most one active SSE stream, but stream implementation is not part of the
  public model.

## AnonymousBrowserIdentity

Publicly observable contract:

- It is represented only by the `__Host-battleship_session` cookie.
- The cookie value never appears in request/response JSON, OpenAPI examples, URL parameters, event
  data, browser-readable storage, logs, metrics, invitations, or problems.
- One valid identity is reused when it creates or joins another game.
- Metadata, ruleset, and health public safe reads ignore any presented capability for authority,
  validation, and session lifecycle; they neither reject nor issue, refresh, or clear the session
  cookie. On create/join and session-required operations, an invalid or unknown presented capability
  produces `401 invalid-session` and a cookie-clearing response; a later explicit attempt may proceed
  without it.
- Losing the cookie loses all associated v1 memberships; no recovery identity exists.

Server-only facts such as raw capability, digest, creation time, and membership lookup are described
as security behavior in the guide but never serialized as model fields.

## GameMembership

| Field | Shape | Visibility/rule |
|---|---|---|
| `seat` | `OWNER` or `GUEST` | Derived from authenticated membership; never accepted from a client. |
| `displayName` | `DisplayName` | Visible to both seats once membership exists; immutable. |
| `ready` | boolean | Visible to both seats; irreversible when true. |

The wire model never exposes capability digest, receipt storage, stream handle, rate-limit key, or
other internal membership state. Membership retention is expressed only through the caller's
authorization and `allowedOperations`; it is not a shared member field. Terminal leave returns 204,
does not create a snapshot revision, and therefore cannot change the other retained member's
serialized members, snapshot, tags, or revisions.

## RulesetSummary

Every game snapshot embeds the selected immutable summary so a consumer never needs a local rules
engine or a mutable discovery lookup to understand that game.

| Field group | Required facts |
|---|---|
| Identity | `id`, stable `labelKey`, schema/version identity. |
| Board | `rowCount`, `columnCount`, ordered `rowLabels`, ordered `columnLabels`, `coordinateBase: 0`. |
| Fleet | Ordered entries with `shipTypeId`, stable `labelKey`, length, count, and whether orientation applies. |
| Placement | Allowed orientations; overlap policy; orthogonal-contact policy; diagonal-contact policy. |
| Fire | Shots per decision; repeat-target rejection; turn-retention policy; automatic-water policy. |
| Start/victory | Secure random starting seat chosen at creation but concealed until play; all-ships-destroyed victory. |
| Disclosure | Cell-state vocabulary, sink disclosure, automatic-water disclosure, terminal board reveal policy. |

Initial immutable instances:

- `sea-battle-10-ship.v1`: 10×10; lengths 4×1, 3×2, 2×3, 1×4; horizontal/vertical;
  no overlap/contact including diagonals; one shot; retain turn on hit/sink; automatically disclose
  water around a sunk ship without counting it as a fired shot.
- `hasbro-classic-2002.v1`: 10×10; Carrier 5, Battleship 4, Destroyer 3, Submarine 3,
  Patrol Boat 2; horizontal/vertical; contact allowed but overlap forbidden; one shot; always transfer
  turn after accepted fire; no automatic water.

Mechanical correction requires a new ruleset ID. `UKRAINIAN` and `MILTON_BRADLEY` are invalid IDs.

## Invitation

| Field | Shape | Rule |
|---|---|---|
| `url` | absolute URI string | Exactly the backend-issued public-base/subpath + `/join/{gameId}#invite=<secret>` shape. |
| `expiresAt` | `Instant` | Earlier of 15 minutes after issuance or effective game expiry. |

Lifecycle: `UNUSED -> CONSUMED`, `UNUSED -> REVOKED` on rotation/abandonment, or
`UNUSED -> EXPIRED`. The state and secret digest are not published. Only create and successful
rotation return `Invitation`; no read endpoint recovers it. The frontend strips and retains the
fragment only transiently, obtains CSRF metadata after explicit Join selection, and then sends
`invitationSecret` in the join body.

Every admitted unsuccessful redemption maps to the same `409 invitation-unavailable`, regardless of
which internal invitation state caused it.

## Game

| Field | Shape | Rule |
|---|---|---|
| `gameId` | `GameId` | Public locator. |
| `ruleset` | `RulesetSummary` | Selected at creation; immutable. |
| `phase` | `WAITING`, `PLACEMENT`, `PLAYING`, `FINISHED`, `ABANDONED` | Server-owned state. |
| `gameVersion` | `Revision` | State-concurrency revision. Starts at 0. |
| `snapshotRevision` | `Revision` | Visible-representation revision. Starts at 0. |
| `startingSeat` | optional `OWNER`/`GUEST` | Selected at creation; omitted until the first playing snapshot. |
| `turn` | optional turn projection | Present only while playing; server-owned firing authority. |
| `terminalOutcome` | optional discriminated union | Present only when finished/abandoned. |
| `deadlines` | `LifecycleDeadlines` | Caller-safe applicable deadlines, never inferred by clients. |

### Phase transitions

| From | Accepted intent/event | To | Public transition |
|---|---|---|---|
| none | create | `WAITING` | owner only; both revisions 0; concealed starting seat; one invitation. |
| `WAITING` | guest join | `PLACEMENT` | consume invite; add guest; refresh idle; both revisions +1. |
| `WAITING` | owner/guest pre-play leave | `ABANDONED` | invitation/gameplay revoked; safe retained views; both revisions +1. |
| `PLACEMENT` | place/move/rotate/remove | `PLACEMENT` | edit actor's fleet; publish privacy-safe snapshot to both; both revisions +1. |
| `PLACEMENT` | first valid ready | `PLACEMENT` | actor readiness locks; both revisions +1. |
| `PLACEMENT` | second valid ready | `PLAYING` | reveal selected starting seat; begin gameplay timing; both revisions +1. |
| `PLACEMENT` | pre-play leave | `ABANDONED` | no placement/fleet statistics disclosed; both revisions +1. |
| `PLAYING` | accepted non-terminal fire | `PLAYING` | authoritative outcome/turn/statistics; both revisions +1. |
| `PLAYING` | terminal fire | `FINISHED` | one winner, full permitted boards/statistics; both revisions +1. |
| `PLAYING` | resign | `FINISHED` | opponent winner; resignation result; both revisions +1. |
| `PLAYING` | leave endpoint | `PLAYING` | no transition; `409 resign-required`. |
| terminal | member leave | terminal | caller membership/stream revoked; revisions unchanged; `204`. |
| active | eligible extending presence | same | idle deadline changes; only `snapshotRevision` +1. |
| active | deadline wins before request | removed/unavailable | no resurrection; current-process evidence may produce 410. |

Read, conditional 304, rejected command, duplicate replay, repeated target, non-extending presence,
heartbeat, reconnect, stream replacement, and terminal membership revocation do not advance either
revision. Every transition that advances `gameVersion` advances `snapshotRevision` exactly once.

## LifecycleDeadlines

| Field | Presence |
|---|---|
| `idleExpiresAt` | Active game only; current 15-minute qualifying-activity deadline. |
| `absoluteExpiresAt` | All retained games; fixed two hours after creation. |
| `invitationExpiresAt` | Only when caller may manage an unused invitation. |
| `effectiveActiveExpiresAt` | Active game; minimum of idle and absolute deadline. |
| `readableUntil` | Finished/abandoned retained-member snapshot; minimum of terminal+5m and absolute. |

At or after a deadline the resource is expired/unavailable. Reads, rotation, stream traffic,
reconnects, failures, duplicates, and rejected/non-extending presence never refresh idle life.

## GameSnapshot

Required base fields:

- `contractVersion`, `apiMajor`, `serverEpoch`, and fixed-per-revision `observedAt`;
- `gameId`, `gameVersion`, `snapshotRevision`, and `gameStateTag`;
- full selected `ruleset` summary;
- `phase`, `callerSeat`, and `members.owner`/optional `members.guest`;
- `allowedGameCommands` and separate `allowedOperations`;
- applicable `deadlines`;
- for `WAITING`, `PLACEMENT`, `PLAYING`, and `FINISHED`, caller's complete `ownBoard` and caller-safe
  `opponentBoard`; for `ABANDONED`, two `RedactedBoardProjection` values instead;
- conditional turn, starting-seat, invitation-management, terminal outcome, terminal boards, and
  terminal-statistics projections.

An unchanged `snapshotRevision` reuses the same `observedAt`. The HTTP `ETag` is not reconstructed
from body fields; it is a header tied to the complete caller representation.

The machine schema is a phase-discriminated union. `ABANDONED` cannot validate ordinary own,
opponent, or terminal boards; every other phase cannot validate the redacted board form. This
conditional boundary makes the abandonment privacy rule structural rather than prose-only.

### Allowed actions

`allowedGameCommands` is a subset of the closed seven-command union. `allowedOperations` is a subset
of `ROTATE_INVITATION`, `SEND_PRESENCE`, `LEAVE_PRE_PLAY`, `LEAVE_TERMINAL`, `REFRESH_SNAPSHOT`, and
`OPEN_STREAM`. A client neither derives commands from phase nor treats endpoint operations as game
commands.

### Board projections

The schema uses distinct board-context unions so privacy-invalid cells cannot be represented as a
normal pre-terminal opponent projection.

- Own cells: `WATER`, `OWN_SHIP`, `MISS`, `HIT`, `SUNK`, `AUTO_REVEALED_WATER`; ship-bearing cells may
  carry caller-authorized `shipId`.
- Pre-terminal opponent cells: `UNKNOWN`, `MISS`, `HIT`, `SUNK`, `AUTO_REVEALED_WATER`; no raw
  placement or ship ID.
- Terminal disclosed boards: complete seat-keyed ship/cell facts after normal victory/resignation
  only.
- Abandoned boards: `RedactedBoardProjection` containing only dimensions and
  `disclosure: REDACTED`; it has no cells, ships, placement, orientation, coordinates, or damage.

`OwnBoard.ships` contains stable `shipId`, `shipTypeId`, placement/orientation when placed, occupied
coordinates, and authoritative condition. Same-length ships remain addressable. Abandoned snapshots
replace both ordinary board projections with the redacted form, so neither placement is structurally
representable.

### Projection privacy matrix

| Fact | Waiting/placement/playing | Normal/resigned terminal | Pre-play abandoned |
|---|---|---|---|
| Caller fleet | complete caller-authorized view | complete | omitted/undisclosed after abandonment as required by safe view |
| Opponent raw placement | never | complete to retained members | never |
| Concealed starting seat | omitted until play | included in terminal history/outcome as applicable | never needed |
| Invitation | only owner create/rotate wrapper, not ordinary snapshot | never | never |
| Capabilities/digests | never | never | never |
| Command history/type during private placement | never; only revision timing/count | never as raw history | never |
| Subscriber/lock/rate internals | never | never | never |
| Terminal statistics | never | required | omitted |

Two games that differ only in undisclosed placement must serialize equivalently for the same caller,
apart from bounded non-sensitive correlation values outside snapshots.

## GameCommandEnvelope

Required fields are `commandId`, `expectedVersion`, and `command`. HTTP `If-Match` must exactly equal
the snapshot `gameStateTag` corresponding to `expectedVersion`.

Closed command variants:

| Discriminator | Payload |
|---|---|
| `PLACE_SHIP` | `shipId`, `anchor: Coordinate`, `orientation` |
| `MOVE_SHIP` | `shipId`, `anchor: Coordinate` |
| `ROTATE_SHIP` | `shipId`, explicit target `orientation` |
| `REMOVE_SHIP` | `shipId` |
| `READY` | no variant fields |
| `FIRE` | `target: Coordinate` |
| `RESIGN` | no variant fields |

`shipId` values are supplied by the authoritative own-fleet draft projection; the client does not
mint domain ship identity. `ROTATE_SHIP` names the resulting orientation rather than "toggle", making
duplicate normalization stable.

Normalized semantic content consists of `expectedVersion` plus the discriminator and its complete
canonical payload: object member order and JSON whitespace do not matter; absent and explicit null
are not equivalent unless the schema permits null. `commandId` is the lookup key, and `If-Match` must
match the same precondition. Duplicate lookup and content equality occur before freshness/domain
validation.

## LeaveEnvelope

Required fields are `commandId` and `expectedVersion`; there is no client-selected phase or result.
`If-Match` must match the same game-state version. Endpoint behavior derives from authoritative phase:

- waiting/placement: versioned abandonment and `200 GameSnapshot`;
- playing: no transition and `409 resign-required`;
- terminal retained membership: revoke caller and return `204`;
- identical retained receipt after terminal revocation: authenticate possession against the receipt,
  restore no membership, and replay `204`.

## CommandReceipt

Receipts are not exposed as internal records. Their observable contract is:

- game-command key: game + membership + `commandId`;
- leave key: game + former/current membership + `commandId`;
- normalized request fingerprint;
- recorded player-safe result (snapshot or 204);
- identical retained replay returns the recorded result before precondition/domain validation;
- changed normalized content returns `409 command-id-reused`;
- at least the latest accepted game command per membership remains until the next command or removal;
- up to two leave receipts per seat remain until game removal;
- no receipt survives process restart.

## PresenceResponse

| Field | Shape | Rule |
|---|---|---|
| `extended` | boolean | True only if this call actually moved the idle deadline. |
| `serverTime` | `Instant` | Observation time for the response. |
| `deadlines` | `LifecycleDeadlines` subset | Current idle, absolute, and effective deadline. |
| `snapshotRevision` | `Revision` | Current caller-visible revision after the decision. |

Presence has no request body. A visible authenticated non-terminal client may call it. The server
permits at most one extension per membership per five minutes; an earlier well-formed call returns
`extended: false`; abuse may return 429.

## TerminalOutcome

Closed discriminator:

- `ALL_SHIPS_DESTROYED`: `winnerSeat` and `loserSeat` required.
- `RESIGNATION`: `winnerSeat` and `loserSeat` required.
- `ABANDONED`: no winner or loser permitted.

Clients never infer outcome from boards.

## TerminalStatistics

Present exactly once on normal-victory/resignation snapshots and absent from every other phase.

```text
terminalStatistics
├── match
│   ├── totalDurationMs
│   ├── placementPhaseDurationMs
│   └── gameplayDurationMs
└── bySeat
    ├── owner
    └── guest
        ├── placementDurationMs
        ├── logicalTurns: DurationAggregate
        ├── shots
        ├── hits
        ├── accuracy { numerator, denominator, ratio }
        ├── shotDecisions: DurationAggregate
        └── fleetCondition { totalShips, untouchedShips, damagedShips, destroyedShips }
```

`DurationAggregate` contains `sampleCount`, `totalDurationMs`, `averageDurationMs`,
`fastestDurationMs`, and `slowestDurationMs`.

Required invariants:

- total match = placement phase + gameplay;
- placement phase = max(owner placement, guest placement);
- non-empty aggregate: positive count; total is sample sum; average/fastest/slowest non-null;
  fastest <= half-up average <= slowest;
- empty aggregate: count and total zero; average/fastest/slowest null;
- hits <= shots; shot-decision sample count = shots;
- accuracy numerator = hits and denominator = shots; ratio null iff shots zero, otherwise half-up to
  four fractional digits;
- accepted hit/sink adds one shot and one hit; miss adds one shot; automatic water/rejected/duplicate
  fire adds neither;
- fleet condition categories are mutually exclusive and sum to selected ruleset fleet count;
- both seats' logical-turn totals partition gameplay duration without overlap;
- owner and guest projections of the same terminal revision contain identical `match` and `bySeat`
  facts; presentation relabels but does not reorder/recalculate them.

## SnapshotEventData

There is no JSON event envelope. The event's `data` validates directly as `GameSnapshot`.

```text
event: snapshot
id: <decimal snapshotRevision>
data: <single-line GameSnapshot JSON>

```

The SSE ID is not `gameVersion`. `Last-Event-ID` never identifies a game or epoch and grants no
authority. Heartbeats are comments and do not carry state.

## ProblemDetail

Required: `type`, `status`, `code`, `correlationId`.

Optional, code-bounded fields:

- `serverEpoch` for recovery-relevant current-process evidence;
- `violations[]` with stable `field`, `rule`, and bounded structured parameters;
- `conflictReason` from a closed non-sensitive reason set;
- `recovery` with stable `action` and optional `retryAfterSeconds`/current revision facts.

No `title`, `detail`, localized message, raw body, stack, exception, secret, cookie, invitation, board,
or internal state is published. The exact code/status/recovery matrix is in
`contracts/problem-catalog.md`.

## HealthResponse

| Field | Shape | Rule |
|---|---|---|
| `status` | `READY` or `NOT_READY` | Project-owned aggregate readiness. |
| `live` | boolean | True for every valid health response; if false, no response exists. |
| `ready` | boolean | True only when new work can be accepted. |
| `reason` | optional stable enum | Required when not ready: `STARTING` or `DRAINING`; no free text. |
| `checkedAt` | `Instant` | Non-sensitive observation time. |

Capacity alone does not make readiness false. The body exposes no components, configuration, game or
stream counts, metrics, secrets, player data, or framework schema.

## Removal and restart behavior

- A provable current-process expired game may produce `410 game-expired` with current epoch.
- A missing game after cleanup or restart produces generic `404 game-unavailable`.
- A process restart creates a new epoch and retains no game, membership, invitation, receipt, replay,
  stream, or rate-limit state.
- Full current snapshots are the only recovery truth; replay is optional.
